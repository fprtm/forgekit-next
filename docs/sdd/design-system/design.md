# ForgeKit Design System — Entry Doc

This is the entry point for "where does a UI thing live in this repo." Read this before adding any component to `src/shared/components/` or a module's `presentation/ui/`.

## Token source of truth

`src/app/globals.css` — the `@theme` block (Tailwind v4). Colors, radius scale, sidebar-specific tokens, and chart colors are all defined there as CSS custom properties and mapped into Tailwind's theme. **Do not** create a parallel token file (TS constants, JSON, etc.) — one format, one place. To change a color or radius globally, edit the CSS variable in `:root` / `.dark`, never hardcode a raw color value in a component.

## Component boundary contract

Three tiers, each answering a different question:

| Folder | Question it answers | Rule |
|---|---|---|
| `src/shared/components/ui/` | "Is this an unmodified shadcn primitive?" | Generated by `bunx shadcn@latest add <name>`. Never hand-edit beyond what shadcn's own CLI would produce. If you need a variant shadcn doesn't offer, wrap it — don't fork it in place. |
| `src/shared/components/{data-table,layout}/` (sibling folders, one per proven pattern) | "Is this composed from primitives and reused by 2+ modules?" | A folder here means the pattern has already proven itself in at least two call sites (e.g. `data-table/` is used by both `products` and `users`). Don't pre-create a folder for a pattern with only one user — that's the module's own `presentation/ui/components/` until a second module needs the same thing. |
| `src/modules/<name>/presentation/ui/components/` | "Is this specific to one module's domain?" | Default location for anything new. Promote to `shared/components/` only on the second real reuse, not in anticipation of one. |

**Adding a new shared pattern**: when a second module needs something already built for a first one, extract it to `src/shared/components/<pattern-name>/` as its own sibling folder (matching `data-table/`'s shape) — not into a generic `patterns/` catch-all. Each pattern gets a folder named for what it is; there is no umbrella folder to file things under "just in case."

## Route strings

All internal navigation paths are defined once in `src/shared/config/routes.ts` and referenced from there — never hardcode a route string (`"/d/..."`) in a component, page, or test. See `docs/sdd/specs/001-phase1-foundation/sds.md` for the full rationale and shape.
